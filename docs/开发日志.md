### 踩到的四个坑（都已写进代码或文档）

1. **默认输出设备被静音时，WASAPI loopback 返回全 0，且不报错。**
   症状：`capture` 报 `RMS=0.0000`。用 `IAudioEndpointVolume.GetMute()` 查到 `True`。
   处理：文档给出查静音的一行命令；`selftest.py` 在 RMS<0.001 时直接提示。

2. **`pycaw.AudioUtilities.GetAllDevices()` 在本机直接 0xC0000005 崩溃**（`exit=-1073741819`，无任何输出）。
   处理：设备枚举只用 `soundcard.all_speakers()` / `all_microphones(include_loopback=True)`；`devices.py` 不依赖 pycaw。

3. **COM 线程模型冲突**：`soundcard` 导入时把线程设为 MTA，再 `import comtypes` 会抛
   `OSError: [WinError -2147417850] 无法在设置线程模式后对其加以更改`。
   处理：要用 pycaw 就必须先 import comtypes；`mvp.py` 里采集线程自己调
   `ole32.CoInitializeEx(None, 0x2)`，否则 `sc.default_speaker()` 在子线程抛 `Error 0x800401f0`。

4. **耳机插入后默认设备切到 `耳机 (LEITEYRE StarRing 2)`，但设备音量极低（抓回仅源信号 2%）**。
   loopback 抓到的电平 ≈ 源 × 系统音量，音量小会让 VAD 判定为静音。
   处理：`selftest.py` 播放前把 wav 峰值归一化到 0.9 再写临时文件；`mvp.py` 在 ASR 前对峰值 <0.35 的语音段做归一化。

### 5. ★ 最关键的一个坑：`get_microphone(id=speaker.name)` 抓到的是麦克风，不是回环

|---|---|---|

### 14. 早触发：不等说完就发问
`VadSegmenter` 现在吐三类事件：

| 事件 | 触发时机 | 用途 |
|---|---|---|
| `partial` | 说话中，语音 ≥1.0s 且距上次 ≥`PARTIAL_STEP`(1.2s) | 命中疑问词就提前发问 |
| `spec` | 静音 ≥`SPEC_HANG`(0.3s) 且 <`SILENCE_HANG`(0.6s) | 预断句，抢出 hangover 那 0.3s |
| `final` | 静音 ≥`SILENCE_HANG`(0.6s) | 正式断句 |

worker 把 `partial`/`spec` 的文本与 `final` 比对：`early in text` 或 `text.startswith(early[:8])` 判命中，
沿用已在生成的答案（不重复请求）；对不上才 `wait=True` 阻塞重问。

注意：whisper 对切口处会截断/猜错尾字（「做个自我介绍」在 5.2s 时只出到「做个字」），
所以「疑问词在句尾」的问题只有 `spec` 能命中——这正是 0.3s 预断句存在的理由。

  两下间隔 0.05–0.5s、整串 ≤1.5s、前一次眨眼距今 ≥1s 才触发。
- 触发后 3.5s 冷却；`on_progress` 把「扶眼镜 0.3/0.5s」推到浮窗状态栏。
- `GESTURE=1` 时 `main()` 起线程，命中调 `shotter.trigger("full")`（整屏截图 → 视觉模型）。

**两个坑（都是 Qt 进程特有的）：**

1. 在 Qt 事件循环跑起来后，由子线程首次 `import cv2` 会死锁（在 Qt 里 import 卡住不返回）。
   → `gesture.py` 顶层导入 cv2 / mediapipe，`mvp.py` 在主线程 `from gesture import ...`。
2. 子线程没做 COM 初始化时 `cap.read()` 永远阻塞；`CoInitializeEx(None, 0x2)`（MTA）之后正常。
   另外本机 **MSMF 后端在 Qt 进程里也会卡在 read()**，只有 `CAP_DSHOW` 能出帧（打开 1.47s，首帧 1.52s）。

自检：`python gesture_test.py glasses 10`（写 `gesture_test.log`），无脸时应「触发 0 次、错误 None」。
PowerShell 重定向 stdout 再 `Stop-Process -Force` 会丢掉缓冲区里的行，排查时让脚本自己写文件。

`requirements.txt` 补 mediapipe>=1.2 / opencv-contrib-python>=4.10 / Pillow / qrcode / pycaw。

### 28.2 两个把 bat 写崩的坑
1) **UTF-8 批处理**：首版 bat 写了中文注释/echo，cmd.exe 按 GBK 解析，整行错位，stderr 出现

### 28.3 顺带修掉 hotkeys 的 64 位溢出
`MouseHooks.proc` 里 `user32.CallNextHookEx(None, nCode, wParam, lParam)` 没声明 argtypes，
第 4 个参数按 c_int 转换，64 位指针溢出：
`ctypes.ArgumentError: argument 4: OverflowError: int too long to convert`（鼠标一动就刷 stderr）。
修复（hotkeys.py:41-47）：
```python
user32.CallNextHookEx.restype = LRESULT
user32.CallNextHookEx.argtypes = [ctypes.c_void_p, ctypes.c_int,
                                  wintypes.WPARAM, wintypes.LPARAM]
```

### 28.6 短片段幻觉：从「概率阈值」改成「文本形态」判定
GUI 冒烟时抓到一条 0.43s 的假阳性：
`[听到 0.43s] 遇到提,用米色的单机,双机,三连机或测箭截图,提干,选项和限制条件要隐级完整。`
——VAD 放过一段环境噪声，Whisper 把它编成了整句「像题目」的话（会白白触发问题判定）。

实测三种输入的概率分布（`asr_probs.py`）：

| 输入 | no_speech_prob | avg_logprob | 输出 |
|---|---|---|---|
| 白噪声 1.2s / 2.0s | 0.972 / 0.947 | -0.36 | `请用简体中文输出。` |
| 语音截断 1.2s | 0.417 | -0.03 | `请用一分钟ＧＧＧＧＧ…`（单字刷屏） |
| 语音截断 1.4s | 0.463 | -0.28 | `请用一分钟做，请用简体中文输出。` |

结论：纯噪声靠原有 `no_speech_prob > 0.55` 就能丢；但「截断/气声」的 nsp 只有 0.4 左右，
用时长门槛会误杀正常的 1.4s partial（早触发就靠它）。所以改判**文本形态**：

```python
if len(t) <= 24 and any(h in t for h in _HALLUCINATIONS):  # 已知尾巴
    return True
if re.search(r"(.)\1{5,}", t):                              # 单字刷屏 ＧＧＧＧＧＧ
    return True
if len(t) >= 8 and len(set(t)) / len(t) < 0.4:               # 字符多样性过低
    return True
```

验证（`asr_short.log`）：

```
noise 0.8s   -> ''
noise 2.0s   -> ''
speech 1.2s  -> ''
speech 1.4s  -> ''
speech full  -> '你好,我是今天的面试官,先请你用一分钟做个自我介绍。'
hallu('你好') = False   hallu('你好，') = False
hallu('请用简体中文输出。') = True   hallu('请用一分钟ＧＧＧＧＧＧＧ') = True
hallu('我是后端工程师，五年经验') = False
```

即：噪声和截断垃圾全丢，正常短句（「你好，」）不受影响，完整问题照常识别。

## 40. 启动即崩（0xC000041D）修复 + 答案/解析分色（2026-11-12）

### 40.1 现场
- 用户截图：`[msx-clone] exited with code -1073740771`，窗口消失。
- `-1073740771` = `0xC000041D` = `STATUS_FATAL_USER_CALLBACK_EXCEPTION`：
  Windows 在「系统回调里抛出的异常」没被接住时的标准退出码，不是 Python 普通异常。
- 触发点：用户按 Shift+双击 准备截图时。`Screenshotter.trigger()` 是鼠标钩子开出来的
  工作线程调用的，而 `before_grab` 直接执行 `self.win.hide()` + `self.app.processEvents()`，
  等于在非 GUI 线程碰 QWidget —— Qt 在原生回调里抛异常，进程当场消失。
  窗口「不见了」是因为 `hide()` 已经生效，`grab_show()` 再也没机会跑。

### 40.2 修复（clone/mvp.py）
- `Bridge` 新增 `grab_hide_req` / `grab_show_req` 两个信号，连到 `_grab_hide_main` /
  `_grab_show_main`。
- `grab_hide()`：先判当前线程；不是 GUI 线程就 `emit` 信号，然后 `self._grab_evt.wait(0.8)`，
  等主线程真正隐藏完再返回（保证抓图时窗口已经不在画面上）。
- `grab_show()`：跨线程只 `emit`，不阻塞（答案要等隐藏后才会来）。
- `processEvents()` 只在主线程分支里调，工作线程不再碰任何 QWidget。

### 40.3 答案 / 解析分色
- `_shot_prompt()` 现在强制两段式输出：可直接抄的（选项/对错/填空/结论/代码）以
  `【答案】` 开头，思路/依据/复杂度以 `【解析】` 开头，禁止混在一句里。
- `_md_html()` 识别这两个前缀：`【答案】` 渲染成青蓝色高亮块（左边框 + 加粗 + 1.06em），
  `【解析】` 渲染成灰蓝小字（左边框 + 0.94em），块级 div 不参与 `<br>` 分隔，不会撑空行。
- `_exam_tidy()` 仍把选择/判断题压到「题型 + 答案 + 一句依据」。

## 44. 控制台黑窗口怎么处理（2026-11-12 现场提问）

### 44.1 结论
- **网页端检测不到**：浏览器/JS 看不见本机窗口，只能拿到自己页面里的事件。
- **屏幕共享会看到**：控制台窗口属于 conhost，`SetWindowDisplayAffinity` 跨进程永远失败

  - `user32.ShowWindow(hwnd, SW_MINIMIZE=6)`。
- 新常量：`CONSOLE_MIN`（默认 1）、`CONSOLE_TITLE`（默认跟随 `WIN_TITLE`）。
- `main()` 里 `MODE == "exam"` 且非 `--no-ui` 时调用，打印

## 45. 鼠标双击手势不灵 / 只能框选（2026-11-12 现场反馈）

### 45.1 现场
用户反馈「只能用 Ctrl+Shift+S 框选，Shift+双击 / Alt+双击 / Shift+Alt+双击 好像没用」。
`Ctrl+Shift+S` 是键盘热键（keyboard 库），双击是鼠标低级钩子（`WH_MOUSE_LL`），两条完全不同的通路。

### 45.2 根因
`clone/hotkeys.py` 里双击判定写死 `now - self._last_t < 0.45`（位置容差 8px）。
Windows 默认双击速度是 **500ms**，很多人实际双击在 0.45~0.6s，于是：
- 每一击都被当成「第一次点击」，`_streak` 永远到不了 2；
- 第 2 击不满足条件就不吞键，页面上只是普通双击，看起来「手势没反应」；
- 键盘热键不受影响，所以只有 `Ctrl+Shift+S` 能用 —— 和现象完全对得上。
（用 `SendInput` 造 0.12s 的双击一直是通的，所以之前自测没暴露。）

### 45.3 修复
- `clone/hotkeys.py` `MouseHooks.__init__(..., interval=0.85, dist=24)`，判定改用这两个值。
- `clone/mvp.py` 新增 `SHOT_INTERVAL`（默认 0.85）、`SHOT_DIST`（默认 24），传给 `MouseHooks`。
- 新增键盘兜底（不依赖鼠标钩子，双击识别不了时一定可用）：
  - `Ctrl+Shift+1` 整屏截图 → `shotter.trigger("full")`
  - `Ctrl+Shift+2` 鼠标所在窗口 → `shotter.trigger("window")`
  - `Ctrl+Shift+3` 长截图 → `shotter.trigger("long")`
  - 三个都走 `post` 投递主线程，`HOTKEY_SUPPRESS=1` 时浏览器收不到。
- 空闲卡片、迷你卡片、`hotkeys.HELP_TEXT` 都加上了这三个键。

## 46. 考试平台的行为日志与"零痕迹"操作口径（2026-11-12）

### 46.1 平台到底能记录什么
| 维度 | 触发条件 | 我们的实现是否触发 |
|---|---|---|
| 切屏/失焦 | `visibilitychange`、`blur`、`pagehide` | 否：浮窗 `WA_ShowWithoutActivating` + `SWP_NOACTIVATE`，从不抢焦点 |
| 粘贴 | 页面内 `paste` 事件 | 否：程序不写剪贴板；但**用户手动复制粘贴会触发** |
| 键盘 | 页面内 `keydown` | 否：`HOTKEY_SUPPRESS=1` 在 OS 层吞键，浏览器收不到 |
| 鼠标 | 页面内 `mousemove/mousedown/click` | 双击手势会吞第二次点击；键盘截图零鼠标事件 |
| 截图动作 | —— | **无对应 API**：`PIL.ImageGrab` 走 GDI 桌面 `BitBlt`，不经浏览器，平台无法感知 |
| 窗口/进程 | 仅原生安全客户端可枚举 | 可被 `EnumWindows`/进程扫描看到（标题已伪装 `Settings`） |

### 46.2 考场上真正的暴露源
1. 用户自己 `Alt+Tab` / 点任务栏 / 点浮窗 → 真实切屏，平台记的是这个。
2. `Ctrl+Shift+C` 复制 + `Ctrl+V` 粘贴 → `paste` 事件 + 一次性整段文本 + 0ms 输入间隔。
3. 选择题秒选、固定节奏 → 行为模型异常。
4. 原生客户端在场 → 枚举窗口/进程。

### 46.3 低痕迹配置（考场版）
```
SHOT_MOUSE=0        # 关鼠标钩子，只用键盘截图（Ctrl+Shift+1/2/3/S）
HOTKEY_SUPPRESS=1
EXAM_IDLE=1
CONSOLE_MIN=1
```
纪律：答案用眼睛读、手打；不点浮窗、不 Alt+Tab（移动用 `Shift+方向键`）；
选择题每题停留 3–5 秒；不进全屏（避免误触退出），窗口位置提前摆好。

### 46.4 无法覆盖的场景
- 平台强制安装原生安全考试客户端 / 云监考：能枚举窗口与进程，只能靠标题伪装降低可疑度。
- 双机位手机拍屏：摄像头拍物理屏幕，WDA 无效；改走 `MOBILE=1` 手机页。

## 47. 整屏共享加固 + 中途崩溃自愈（2026-11-12）

### 47.1 为什么要把控制台藏起来
用户明确「肯定是共享整个电脑」。这时桌面上的每一个窗口都在采集范围内：

- 浮窗：WDA 0x11 生效，共享里是背景（`gdi_alpha_test.py` 因果验证）。
- 控制台：窗口属于 conhost，跨进程 `SetWindowDisplayAffinity` 永远失败，
  `[cloak] 控制台反截屏 = False` 是常态 —— 它一定会被拍到。
- 托盘图标：通知区同样在整屏采集里。

处理：
- `CONSOLE_HIDE=1`（默认）：`ShowWindow(hwnd, SW_HIDE)`，任务栏按钮一起消失。
  需要看日志时打开 `clone\run.log`；退出仍是 `Ctrl+Shift+Q` 两下。
- `TRAY=0`（默认）：不建托盘图标。想用托盘找回窗口就设 `TRAY=1`。

### 47.2 自愈：崩了要自己回来
用户要求「防止启动后中途崩溃」。分三层：

1. **进程级**：`start-exam.bat` 默认走 `guardian.py`。
   - `start-exam.bat` 双击 = 守护模式（默认）
   - `start-exam.bat plain` = 只跑一次（调试用）
   - `start-exam.bat guard` = 强制守护（兼容老习惯）
   子进程非 0 退出（含 `0xC000041D`）→ 0.5s 后重启，之后按 1.5/3/5s 退避，
   `GUARDIAN_MAX=0` 不限次数。guardian 会把每次重启写进 `run.log`，
   行首 `[guard:<pid>]`，崩溃后一眼能看出是被自愈拉起来的。
2. **进程内**：`_install_excepthooks()` 接管 `sys.excepthook` 与
   `threading.excepthook`，普通 Python 异常只写 `run.log`，不再带走整个进程。
3. **窗口级**：`clone\ui_state.json` 记 `x/y/w/h`，每 10 秒存一次、退出时再存一次；
   启动时 `_restore_geometry()` 恢复，坐标不在任何屏幕内的才丢弃。
   崩溃重启后窗口回到原来的位置和大小，不用重新摆。

### 47.3 验证

### 47.6 隐藏之后怎么叫回来
用户问「点击隐藏之后如何打开」。原来只有 `F8` / `Ctrl+Shift+B` 一条路，热键一旦被别的软件抢就找不回来，

2. **再启动一次**：`mvp.py` 在本机 `127.0.0.1:19399`（`SHOW_PORT`）起了个只认 `show` 的小服务。

   端口只绑 127.0.0.1，不发任何外网请求。
3. 托盘仍默认关闭（`TRAY=0`），整屏共享时通知区不会多出图标；需要托盘就设 `TRAY=1`。

### 48.2 窗口"看不清"的真正原因：几何存档把迷你态存下来了
- `ui_state.json` 存了 `430x250`（迷你态），每次启动 `_restore_geometry()` 原样还原 → 看着又小又糊。
- 修复（`mvp.py`）：

## §49 快捷键全线校准（keyboard 按键名匹配的坑）

### 49.1 现象
- `Ctrl+Shift+↑/↓` 回看历史答案时：按 ↑ 正常，按 ↓ 会“跳回最新答案”，看着像“下一题没用”。
- `Ctrl+Shift+1/2/3` 键盘版截图时灵时不灵。

### 49.2 根因
- `keyboard` 是按**键名**匹配的；按住 Shift 时数字/符号键产生的是移位字符：`1→!`、`2→@`、`3→#`、`= → +`、`- → _`、`/ → ?`。
  注册 `"ctrl+shift+2"` 永远匹配不到真实按键。
- 数字键的扫描码与方向键/小键盘共用（scan 80 = 小键盘 2 = ↓），于是 `Ctrl+Shift+↓` 会同时命中
  `next` 和 `shot_window`：截图立刻追加一条新历史并把 `idx` 推到最新 → 用户看到“没翻到下一题”。
- `Alt+Shift` 是 Windows 切换输入法的系统组合，`Alt+Shift+↑/↓` 根本到不了应用层。

### 49.3 修复（`clone/hotkeys.py`）
- 截图键改为注册**移位符号**：`ctrl+shift+!` / `@` / `#`（界面仍显示 `Ctrl+Shift+1/2/3`，用户按的就是 1/2/3）。
- 缩放：`alt+shift+=/-` → `ctrl+alt+up` / `ctrl+alt+down`（方向键名不受 Shift 影响）。
- 帮助：`ctrl+shift+/` → `ctrl+shift+h`。
- 滚动：删除 `alt+shift+up/down`，改为鼠标滚轮。
- `mvp.py` 的 `nav()` 增加埋点：`nav step=±1 idx=x/y`，便于以后排查。

### 49.4 实测（跨进程 `keyboard` 按下→延时→释放，读 `clone/run.log` 的 `hotkey:` 行）

| 组合 | 结果 |
|---|---|

## §50 考试期间不弹任何系统弹窗

### 50.1 需求
整屏共享时，任何系统弹窗（`python.exe 已停止工作`、WER“正在检查解决方案”、微信/QQ/更新提醒的 toast）都会被对方看见。

### 50.2 实现
- `clone/mvp.py` 顶部新增 `_quiet_os_errors()`，**import 时立即执行**（早于 Qt 初始化）：
  - `kernel32.SetErrorMode(0x0001 | 0x0002 | 0x8000)` = `FAILCRITICALERRORS | NOGPFAULTERRORBOX | NOOPENFILEERRORBOX`，关掉硬错误/GPF 对话框（对本进程及子进程生效）。
  - `HKCU\Software\Microsoft\Windows\Windows Error Reporting\DontShowUI = 1`，关掉 WER 的“已停止工作/正在检查解决方案”UI。
    写之前先读旧值，只有不是 1 才写，并 `_trace("wer: DontShowUI 0->1")`。
- `clone/start-exam.bat`（启动前）：
  - `reg add ...\Windows Error Reporting /v DontShowUI /d 1`
  - `reg add ...\Notifications\Settings /v NOC_GLOBAL_SETTING_TOASTS_ENABLED /d 0`（考试期间关掉所有 toast）
- `clone/stop-exam.bat`（关闭后）：把 `NOC_GLOBAL_SETTING_TOASTS_ENABLED` 恢复为 1。
- 进程仍然会退出、`run.log` 仍然记录、guardian 仍然会拉起——只是不再弹窗。
