# 检测风险评估（牛客 / 笔试平台 / 面试会议）

> 结论先行：浏览器型平台（牛客、多数在线笔试）**看不到进程、钩子、窗口枚举、局域网端口**，
> 真正会触发的是三类：①浏览器失焦（切屏判定）②摄像头争抢 ③共享屏幕时浮窗被抓拍。
> 原生监考客户端（少数）才可能枚举进程/窗口/钩子——那种场合用「手机 / 语音播报 / no-ui」模式最稳。

## 检测面与等级

| 级别 | 检测途径 | 本工具暴露点 | 是否会触发 |
|---|---|---|---|
| **P0** | 浏览器 `blur`/`visibilitychange`（牛客切屏判定） | 用户点击/拖动浮窗会让浏览器失焦 → 判「切屏」；**已加固**：不夺焦点、框选层不抢焦点、手势吞点击 | 仅在直接点浮窗时 |
| **P0** | UI Automation / MSAA 读窗口文本 | 浮窗是真实窗口，`SetWindowDisplayAffinity` 只挡视觉、**不挡 UIA**，原生代理可读出答案文字 | 原生代理才可能 |
| **P1** | 摄像头独占 | `GESTURE=1` 打开摄像头；监考也用摄像头 → 争抢/指示灯亮 | `EXAM_SAFE=1` 强制关，不触发 |
| **P1** | 截屏/录屏共享（腾讯会议、Zoom、监考软件） | 浮窗用 `WDA_EXCLUDEFROMCAPTURE` 隐藏，本机 Win11 对 WGC/DXGI 与 GDI 均实测生效；**Win10 <2004 无效**，老系统会露 | 视系统版本 |
| **P1** | 进程枚举 | `python.exe` 进程名，原生监考可枚举 | 原生代理才可能 |
| **P2** | 全局钩子（`keyboard` 键盘钩、`MouseHooks` 鼠标钩） | 反作弊常把「带 WH_KEYBOARD_LL / WH_MOUSE_LL 的进程」当特征 | 原生反作弊才可能 |
| **P2** | 剪贴板变化 | `Ctrl+Shift+C` 写入剪贴板，页面 `clipboardchange` 可感知 | 需权限，少 |
| **P2** | 局域网端口扫描 | 手机页绑 `0.0.0.0:8765`，原生代理可扫到；`/api/state` 仅 token 门禁、无速率限制 | 原生代理才可能 |
| **P3** | 热键冲突 | `F10`（浏览器=菜单栏）、`ctrl+shift+up/down`（牛客可能自定义） | 撞了就换键 |
| **P3** | GPU/CPU 尖峰 | ASR 0.21s/段、视觉 1.4s/题，短暂 | 低 |
| **P3** | 外联网络 | 只连 `127.0.0.1`，**无任何外网连接** | 不会 |

## 关键机制（为什么有的会、有的不会）

- **WDA_EXCLUDEFROMCAPTURE（0x11）**：只影响「别人捕获本窗口的画面」，让浮窗在共享屏幕/监考截图里消失。
  **本机实测（2026-11-12，Win11 build 26200，`clone/gdi_alpha_test.py`，不透明窗口 + WDA on/off 因果对照）**：
  ```
  no-wda:        opaque=(255,0,0)   translucent=背景   ← 不透明窗口能被 GDI 整屏抓到
  wda-0x11:      opaque=背景        translucent=背景   ← WDA 生效后抓不到
  wda-off-again: opaque=(255,0,0)   translucent=背景   ← 关掉 WDA 又出现，因果成立
  ```
  - 对 **Windows.Graphics.Capture / DXGI** 捕获生效（Win11 截图工具、OBS、Teams/Zoom/腾讯会议、浏览器 `getDisplayMedia`）；
  - 在本机 Win11 上对 **GDI BitBlt**（PIL `ImageGrab`、部分老式监考/录屏）**同样生效**——此前 `wda_ctl.py` 的「设了 0x11 仍截到红色」是测试缺陷（句柄/时序不对），已用上面的 on/off 对照推翻；
  - 它**不影响**：UI Automation（可读文本）、窗口枚举（`EnumWindows` 仍看得到标题 `Settings`）、以及 **Windows 10 2004 之前**的捕获（老系统上会露）。
  - 仍保留可选的**幽灵窗** `EXAM_GHOST=1` 作为第二层（启动隐藏、答案到达才出现 10 秒），但**默认不启用**：默认是常驻可见 + 空闲快捷键卡片（`EXAM_GHOST=0`、`EXAM_IDLE=1`）。
- **浏览器（牛客、HackerRank、LeetCode、CoderPad）**：网页没有权限枚举别的进程、全局钩子、
  局域网端口、窗口句柄。网页唯一能感知的是**本页失焦/切屏**（`blur`/`visibilitychange`）、
  **摄像头/麦克风占用**（`getUserMedia` 冲突）、**剪贴板**（需授权）。因此浏览器型平台的风险面收窄到这三条。
- **腾讯会议 / Zoom / 飞书 面试**：对方看的是「共享屏幕」。浮窗被 WDA 隐藏后**对方看不到**；
  但腾讯会议要勾「视频流畅度优先」、Zoom 用「带窗口筛选的截屏」，否则可能仍显示。
  会议软件本身**看不到**我们的进程/钩子。
- **摄像头（GESTURE=1）**：Windows 默认一个摄像头一次只能给一个进程。若监考同时要用摄像头，
  会有一方失败（或指示灯亮、权限冲突弹窗）。Win11 26400+ 可开「允许多个应用同时使用照相机」，
  Win10 无此能力。**面试/笔试时建议 GESTURE=0**，靠鼠标手势截图即可。

## 本轮加固（代码已实现，2026-11-09）

| 加固 | 实现 | 效果 |
|---|---|---|
| 热键不外漏 | `hotkeys.install(suppress=True)`，`HOTKEY_SUPPRESS=1` | 浏览器收不到 `Ctrl+Shift+B`（书签栏）、`Ctrl+Shift+S`（另存为）等，平台键盘监控也看不到这些组合 |
| 鼠标手势吞点击 | `MouseHooks.proc()` 触达阈值后 `return 1` | 触发截图的那次双击不落到页面上，页面既不切屏也不弹右键菜单 |
| 框选不抢焦点 | 框选层 `WindowDoesNotAcceptFocus + WA_ShowWithoutActivating` | 拖框时浏览器**不失焦**，不触发牛客切屏判定；Esc 不可用，改右键取消 |
| 框选层反截屏 | 框选层也 `SetWindowDisplayAffinity(0x11)` | 共享屏幕/录屏里看不到框选遮罩 |
| 截图前隐藏自己 | `SHOT_HIDE_UI=1` → `grab_hide()/grab_show()` | 截出来的图里没有自己的浮窗，避免"答案套答案" |
| 控制台反截屏 | `CLOAK_CONSOLE=1` → 控制台 hwnd 设 `0x11` | 双击 bat 启动时，日志本地可见，共享/录屏里整块消失（重定向或无控制台时返回 False，正常） |
| 隐身保活（5 秒） | `STEALTH_KEEPALIVE=1` → `Overlay._stealth_main()` QTimer 每 5s 重设 `0x11` + TOPMOST | 驱动重建窗口/切换 DPI 后 WDA 会悄悄失效，官方 v0.3.100 同样 5 秒保活一次；本实现含 grid 与 console |
| 笔试安全模式 | `EXAM_SAFE=1` | 强制 `GESTURE/MOBILE/TTS=0`（不碰摄像头、不开 8765、不发声），窗口启动即隐藏+点击穿透，`F8` 显示 |
| 连拍节流 | `Screenshotter._loop()` 队列非空时 `sleep(1.0)` | 两张截图至少隔 1 秒，避免同一页被截两遍、也符合官网行为 |
| 图形准备页不抢焦点 | `Grid` 用 `WindowDoesNotAcceptFocus + WA_ShowWithoutActivating` + 自身 `SetWindowDisplayAffinity(0x11)` | `Ctrl+Alt+G` 画辅助线时浏览器不失焦、不进录屏，等于多一个不触犯切屏的"草稿纸" |
| 无外联 | 只连 `127.0.0.1:19300` | 监考抓不到外部域名/IP |
| 窗口形态（默认常驻） | `EXAM_GHOST=0` + `EXAM_IDLE=1`：未截图时显示快捷键卡片；截图瞬间 `grab_hide()` 隐身，抓完 `grab_show()` 恢复 | 共享/录屏看不到（WDA 0x11 本机对 WGC 与 GDI 均实测生效）；自己截图也不会把自己截进去。需要更隐蔽时改 `EXAM_GHOST=1` 幽灵窗 |

仍存在的边界：`keyboard` / `WH_MOUSE_LL` 钩子本身在原生反作弊里是特征（浏览器看不到）；
`python.exe` 进程名可被原生客户端枚举；UIA 仍能读浮窗文字。要彻底归零就走
`EXAM_SAFE=1` + `python mvp.py --no-ui`（无窗口）或 `TTS=1`。

## 牛客专用对策（按风险从高到低）

1. **永远别用鼠标点浮窗**：一点就触发浏览器 `blur` → 切屏判定。全程用**热键**，或按 `F9` 开启
   点击穿透（`WS_EX_TRANSPARENT`，鼠标事件直接穿过浮窗落到页面，不抢焦点）。`WA_ShowWithoutActivating`
   已保证「显示浮窗不夺焦点」，所以只要不点它就不会失焦。
2. **摄像头留白**：笔试别开 `GESTURE=1`。
3. **高危考试（原生监考客户端）用安全模式**：`MOBILE_HIDE=1`（第一题后本机窗口隐藏，答案在手机看），
   或 `TTS=1`（语音播报，窗口可完全隐藏），或直接 `python mvp.py --no-ui`（无窗口，纯控制台）。
   没有窗口就没有 UIA 可读、没有进程窗口枚举、没有截屏风险。
4. **进程名**：若监考是原生客户端，`python.exe` 可被枚举。需要时可 `PyInstaller` 打包成普通名
   （如 `Settings.exe`）——但**默认不打包**，因为绝大多数浏览器平台枚举不到进程。
5. **别用 `Ctrl+Shift+C` 复制答案**（剪贴板可被感知）；需要看代码就开答案滚动或截图。
6. **热键冲突**：牛客若把 `ctrl+shift+up/down` 用了，改 `hotkeys.py` 的 `table` 里那两行再重跑。
7. **系统版本确认**：共享屏幕场景先在 `Win11` 上验证 WDA 生效（本机已实测 `WDA_EXCLUDEFROMCAPTURE = True`）；
   若在 Win10 2004 之前，浮窗会出现在共享里，只能用手机/语音模式。

## 结论

- 牛客、LeetCode、HackerRank、CoderPad 等**浏览器平台**：风险主要是「点浮窗→失焦→切屏」和「摄像头争抢」。
  对策 1、2 即可规避，**可以放心开浮窗**（配合 F9 点击穿透）。
- 腾讯会议/Zoom/飞书面试：浮窗已隐藏，**对方看不到**，但确认会议软件开启了「视频流畅度优先/截屏筛选」。
- 少数原生监考客户端：风险在 UIA 读文本、进程枚举、钩子特征——**用手机 / 语音 / no-ui 模式**即可归零。
