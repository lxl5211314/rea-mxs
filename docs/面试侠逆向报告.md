## 3. 鉴权与计费（最关键的发现）

### 3.1 凭据模型：激活码 = 全部身份
`bundle_pretty.js:9118`
```js
const Uo={userId:"user_id",activationCode:"activation_code",remainingMinutes:"remaining_minutes",
          isUnlimited:"is_unlimited",unlimitedExpiresAt:"unlimited_expires_at",
          deviceInstallId:"device_install_id"};
```

`bundle_pretty.js:9408` — 全局请求包装：
```js
async function y0(e,t={}){
  const n=await M0();                       // 读 auth.json 里的 activation_code
  if(!n) throw new Error("缺少激活码，请先登录");
  const r=new URL(e,WB);
  r.searchParams.set("code",n);             // ← 凭据放 query
  ...
}
```
- **没有 Bearer、没有 HMAC、没有时间戳、没有 nonce**。`?code=` 即鉴权。
- 上传走 `s8()`（`:9445`）同样拼 `code` 到 query（multipart）。
- 设备头 `HB()`（`:9170`）只在登录/换绑类接口带：
  `x-msx-device-id`（`device_install_id`，首次 `crypto.randomUUID()` 落盘）、`x-msx-client-type`=`desktop_${平台}`、`x-msx-app-version`、`x-msx-os-version`。

### 3.2 时长
- 本地缓存 `remaining_minutes`，每 10 s（`WN=1e4`）调 `POST /api/verify-client-code {code}` 刷新；超时上报 `desktop_remaining_time_sync_fail / watchdog_10s`。
- 刷新失败不阻断使用（仅提示），→ **断网可继续用，扣费在服务端**（推断：离线期间不扣）。
- `is_unlimited` 由服务端算，客户端只读；`unlimited_expires_at` 过期则 `$B()` 判 false。

### 3.3 封禁/失效
- `ACCOUNT_BANNED` → 弹「账号已被封禁，请联系客服」，清空凭据，踢回 `/code`。
- 401 且返回 code 与本地一致 → `msx-auth-invalid`，清凭据；**已在面试/笔试/小抄页时允许打完本场**（`duration:8e3` 提示）。

**风险**：`?code=` 会进代理日志、浏览器历史、Referer、崩溃报告的 URL 字段。任何能看到一次请求的中间层都能完整冒用账号。

## 5. 面试主链路：`/ws/asr`

### 5.1 握手（`:19580-19601`，系统音频 `:20622-20638`）
```js
const u = new URL("wss://backend.mianshixia.cn/ws/asr");
u.search = "";
u.searchParams.set("data", b64url(JSON.stringify(payload)));
u.searchParams.set("channel", "system" | <mic id>);
```
payload（麦克风）：
```json
{"user_id":"...","coop_room":"...","manual_answer":true,"audio_codec":"opus"}
```
payload（系统音频额外）：
```json
{"long_question_optimization":bool,"capture_trace_id":"...","dual_device":true}
```
**注意：整条 WS 无 `code`、无 token，只有 `user_id`。** 采样率 16 kHz，`audio_codec=opus` 时原生侧 Opus，否则 PCM 帧 base64。

### 5.2 上行
- 原生采集 → `pcm_base64` / `opus_base64` 事件 → 前端重编码 → `ws.send(Uint8Array)`。
- 静音门限：能量 < 0.01 仍发送但计数（`*_low_energy_sent`），避免服务端 VAD 饥饿。

### 5.3 下行消息类型（`:19499-19531`）
| type | 关键字段 |
|---|---|
| `transcript` / `result` | `text, is_final, utterances[], questions[], question_detection, is_me, remaining_ms, grace_remaining_ms, time_expired, extension_active/granted, countdown_active, server_generated_at_ms` |
| `questions_detected_enhanced` | `questions[], is_final, source:"grpc_enhanced"` |
| `ai_answer_start` / `ai_answer_delta` / `ai_answer_quick` / `ai_answer_complete` / `ai_answer_error` | `question_key, is_follow_up, delta, ...` |
| `question_translation` | 翻译对照 |
| `voice_question_result` | 语音提问识别结果 |
| `voicematch_correction` | `text, score, start_time, end_time`（声纹纠错，判断是否本人） |
| `speaker_update` | `is_me, source:"voice_verification", async` |
| `writing_followup` | 笔试追问 |

即：**问题检测、答题、翻译、剩余时长、声纹判定、倒计时全在同一条 WS 的下行**。客户端只做渲染。

### 5.4 断线与降级
- 连接超时 60 s（`Rt=6e4`）、断开 3 s。
- 声明 opus 却收到 PCM → 自动 `set_audio_opus_enabled({microphone:false})` 回退。
- 系统音频重启退避，最长重试若干次（`restart:*` 事件）。

## 7. 隐身系统（三层）

### 7.1 第一层：系统级防截屏
- `SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)`，命令 `enforce_capture_protection`。
- 返回结构 / 状态字段（serde 拼接块）：
  `requested, visible, actualVisible, nativeAccepted, nativeState, protected, partialProtection, readback, affinity, setSucceeded, lastError, win11KernelBug, layeredWindow, build`
- `win11KernelBug` / `layeredWindow` 是**已知兼容性坑的分支**：Win11 某些 build 上分层窗口设置会失败，需要回读校验。
- 前端兜底：`enforce_capture_protection` 失败 → 上报 `capture_protection_failed`（带 `consecutive_failures`），并按 5 s 间隔重试（`:36671`）。

### 7.2 第二层：看护自愈（`msx-capture-guard.exe`）
字符串证据链：
- 枚举：`Process32FirstW/NextW`、`EnumWindows`、`GetWindowRect`、`IsWindowVisible`
- 归属校验：`Open MSX owner`、`PID/window ownership validation`、`Top-level window validation`、`Another installation shares the MSX executable name; its stealth is left untouched`
- 注入：`LoadLibraryW`（`Load companion DLL locally`）、`OpenProcess`、`VirtualProtect`、`WriteProcessMemory`、`CreateRemoteThread`、`GetProcAddress(ClearCaptureAffinity)`、`NtQueryInformationProcess`
- 拒绝条件：`Architecture mismatch; use a matching build`、`Target runs at higher integrity; injection is not permitted`、`Target belongs to another user`、`Restart skipped: the guard and the target differ in integrity level or logon session`
- 状态机：`cleared` / `cleared_blank` / `reprotected` / `readback_unknown` / `transient` / `uncertain` / `permanent` / `own_instance_skipped` / `injection_failed` / `injection_retry`
- 崩溃看护：`wevtapi.dll` 读 `Windows Application Error`、`windows_event_xml`、`target_crashed` / `target_exited` / `target_restarted`
- 日志：`{"kind":"capture_guard","at_ms":…}`，含 `pid, process_name, exit_code, width, uniform_blank, sample:{sampled, attempt, status}`

**机制还原**：guard 周期性对宿主窗口做「解除保护 → 截图 → 判断是否整屏 uniform_blank → 重新加保护」，以此**自检隐身是否真的生效**；宿主崩溃就重启并重新注入。dll 只导出一个 `ClearCaptureAffinity`，是"解除保护"的最小载荷——这正是自检需要的动作。

### 7.3 第三层：消失（伪装 / 穿透 / 隐藏）

## 8. 反检测与协作

### 8.1 键盘守卫（Windows）
- 命令：`keyboard_guard_get_state` / `keyboard_guard_configure({patch})` / `keyboard_guard_set_session_active({active})`；事件 `keyboard-guard-status`。
- 状态：`health: active | degraded | off`；degraded 文案「请检查快捷键或关闭键盘保护」。
- 目的：全局快捷键必须能在**别的窗口有焦点**时生效（面试时焦点在会议软件上），所以用低级键盘钩子；同时解决热键冲突（`register_global_shortcuts` 失败会自动重绑，`auto_rebind`，提示「快捷键冲突已自动切换」）。
- 附加：`ANe()` 在 document 捕获阶段拦截鼠标按下/抬起（`stopImmediatePropagation` + `preventDefault`），5 s 节流——用于小窗防误触/防被外部脚本点。

### 8.2 网络守卫
- `network_guard_status`；失败文案「联网保护未能启用，其他软件限制网络时可能断线」。
- 推断：为自身进程/域名加网络豁免或本地代理旁路，避免被第三方防火墙/抓包工具/校园网客户端掐断。具体实现未反汇编（Rust 侧）。

### 8.3 动作捕捉截屏
- `vision_bundle-hN_Qu4Za.js` = MediaPipe tasks-vision（128,667 B）。
- 手势默认 `nose`（摸鼻子），可换；状态含 `enabled/gesture/running/phase/text/sub/faceOk/error`。
- 触发链：摄像头帧 → 手势 → `capture_screenshot`（不碰键盘，规避"查键盘"）。

### 8.4 双机位 / 手机联动（coop）
- 云中继：`wss://backend.mianshixia.cn/ws/coop-relay`；房间号 `relay_room`，正则 `^[A-Za-z0-9_-]{8,64}$`（`coop_status` 获取）。
- 局域网：`scoop_broadcast(payload, lanOnly)`，同 Wi-Fi 直发（不依赖云）。
- 广播载荷类型：
  - `desktop-state` `{hidden, caps:["desktop-state","gesture-remote","screenshot-status"], version, opacity, scale, theme, questionListOpen, helpOpen}`
  - `question-selected` `{questionKey, pinned, pendingKey, pendingCount, pendingRemainingMs}`
  - `screenshot-status` `{stage, message}`（capturing / uploading / done / failed / cancelled）
  - `gesture-state` `{enabled, gesture, running, phase, text, sub, faceOk, error}`
  - `session-started` `{mode:"interview", view:"answers"}` / `session-ended`
- 反向控制：手机 → PC 的 `coop-cmd-start` / `coop-cmd-show` / `coop-cmd-hide` / `coop-cmd-exit`。
- 双机位答题：`upload_screenshot_stream` 带 `doubleDevice:true`；播报用 `resources\dual-device-*.wav`（welcome/thinking/captured）+ `play_dual_device`。
- 自测：`self-test-interviewer.wav` + `play_self_test_clip`。

## 9. 数据与隐私面

`POST /api/client-logs` 上报的埋点（`pn()` / `is()`）值得单独看：
- 答题链路：`desktop_answer_first_received_time`、`desktop_answer_full_time`、`desktop_answer_failed`，带 `answerRequestId`、`durationMs`。
- 快捷键诊断：`shortcut_diag_{from}_{to}`，带 `scope, shortcut_id, direction`。
- 原生失败：`take_native_failure_records` → `desktop_capture_guard / desktop_network_guard / desktop_rust_panic / desktop_native_crash / desktop_process_died / desktop_webview_silent / desktop_gpu_snapshot`。
- **最敏感**：`exam_browser_page_reference`（`:18727`）把 `beforeText / afterText / pageText` 放进 `context` 上传——即**笔试网页的正文内容会被发回服务端**。
- `screenshot-upload-diagnostic` 把上传过程上下文并入。

结论：除答题本身外，笔试页面文本、失败堆栈、设备与版本、快捷键配置都会外传。
